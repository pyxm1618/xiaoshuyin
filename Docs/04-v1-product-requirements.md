## 1. V1 的目标

小树荫 V1 只做一件事：

> **把一个儿童青少年数字使用问题，从“家长不知道怎么办”推进到“形成判断、执行方案、持续跟踪、复盘调整，并得到真实结果或正确退出”。**

V1 不是一次问答，不以“AI 已经给出建议”为完成。

完整闭环是：

```text
进入
→ 描述问题
→ 了解家庭与问题
→ 判断当前主要问题
→ 确认目标
→ 制定方案
→ 执行
→ 主动/主动返回式跟踪
→ 收集反馈
→ 复盘
→ 调整或继续
→ 维护
→ 稳定改善 / 无需干预 / 退出 / 超范围 / 转介
```

V1 首场景为：

> **儿童青少年手机、平板、电脑、游戏机等数字使用困扰。**

数字设备使用只是切入口，不预设“使用时间长”就是根因。

## 2. V1 用户与参与者

### 2.1 主要用户

主要用户是：

> **正在面对未满 18 岁孩子教育、行为、情绪、学习或亲子关系问题中的数字使用困扰，并不知道如何处理的家长。**

V1 面向中文家庭，主要服务国内用户；不以技术原因把港澳台概念性排除，但真实登录、通知、服务资源和合规能力按实际可用范围显示。

不设置未经专业依据验证的统一最低年龄。

### 2.2 参与方式

V1 采用：

> **家长可以独立开始；孩子按需要参与。**

孩子可以：

- 接受邀请；
- 查看明确共享给自己的内容；
- 表达本人意见；
- 对本人任务反馈；
- 拒绝参与；
- 中途退出。

不要求全家注册。

V1 不建设完整的多人家庭社交空间和长期私人聊天体系；但基础的身份、来源、可见范围和隐私隔离必须存在。

### 2.3 角色边界

| 角色 | V1 可以做什么 | 明确不能做什么 |
|---|---|---|
| 家长主账号 | 发起问题、提供观察、确认目标和方案、执行与反馈、邀请孩子 | 不替孩子制造“本人同意”，不能读取未获授权的孩子私人内容 |
| 受邀孩子 | 表达本人意见、确认本人相关内容、反馈本人任务 | 不读取家长私人原话或其他无授权资料 |
| 未注册家庭成员 | 由家长注明来源后转述 | 转述不能升级为本人直接确认 |
| 内容/专业人员 | 审核专业知识、规则、边界、示例与风险内容 | 不默认逐个方案人工审批 |
| 产品/运营人员 | 管理开放范围、资料请求、质量和真实人工事项 | 不因为是内部人员就拥有全量家庭正文访问权 |
| 真实具备条件的专业复核人员 | 处理规则明确要求的异常和安全事项 | 不虚构“专家正在审核”、不承诺不存在的即时服务 |

## 3. V1 范围

### 3.1 纳入

V1 纳入：

- 手机、平板、电脑、游戏机等数字使用问题；
- 作息、睡眠、必要学习与联系、线下活动等与当前问题直接相关的因素；
- 家长行为和家庭沟通；
- 数字使用是否只是其他问题表现出来的症状；
- 目标、方案、任务、执行、反馈、复盘、调整；
- 持续跟踪；
- 维护与复发；
- 必要的孩子参与；
- 安全中断和正确转介；
- 多年家庭资料连续保存。

### 3.2 不纳入

V1 不建设：

- 多个主要问题同时推进；
- 完整家庭多人私人空间；
- 其他儿童问题的完整干预流程；
- AI 心理/精神疾病诊断；
- 危机救援服务；
- 实时家庭调停；
- 实时语音咨询；
- 跨家庭相似案例推荐；
- 行为预测；
- 支付、订阅、退款体系；
- 机构平台；
- 全年龄服务。

识别出其他问题不等于 V1 有能力继续治疗/干预该问题。

## 4. V1 核心产品原则

### 4.1 一个家庭当前只推进一个主要问题

系统可以记录多个候选问题，但只有一个当前主要个案。

需要切换时：

- 说明为什么切换；
- 保存旧进度；
- 处理旧任务和提醒；
- 家长确认后切换；
- 安全问题可以优先中断普通顺序。

### 4.2 用户说了什么，与事实是什么，必须分开

至少区分：

- 本人陈述；
- 家长观察；
- 家长转述；
- 其他家庭成员转述；
- 手工录入的设备记录；
- 工作人员记录；
- AI 假设；
- 已确认信息。

例如：

> 妈妈说“孩子每天玩六小时”

首先是：

> **妈妈的陈述**

不是自动成为：

> **孩子每天确定玩六小时的客观事实。**

不同来源互相冲突时允许：

> **暂时无法判断。**

### 4.3 AI 不能替用户和专业规则做最终决定

AI 可以：

- 理解表达；
- 提出追问；
- 总结；
- 提出候选判断；
- 提出目标；
- 提出方案；
- 提出复盘建议。

AI 不能独立：

- 把推测改成事实；
- 代替家长确认目标；
- 代替孩子确认本人意见；
- 启用实质方案；
- 解除安全状态；
- 声称外部转介已完成；
- 把未知写成改善；
- 关闭个案。

### 4.4 流程严格，交流自然

系统必须保证关键条件和专业步骤不被跳过。

但交互不能机械化。

已经在本次或历史中可靠获得的信息：

> 不应机械重复询问。

允许自然确认、补充和纠正。

### 4.5 没有证据时允许“不知道”

系统必须明确区分：

- 已知；
- 不知道；
- 尚未收集；
- 明确拒绝回答；
- 不适用。

不能把空值变成“否”或“0”。

## 5. V1 用户旅程

### 5.1 普通路径

1. 家长进入小程序，了解服务范围、AI 边界、资料用途和当前开放方式。
2. 登录并完成必要授权。
3. 建立最小家庭与孩子资料。
4. 描述当前困扰。
5. 系统通过自然对话和少量结构化确认完成必要信息收集。
6. 系统展示：
   - 当前知道什么；
   - 信息来自谁；
   - 哪些仍然不知道；
   - 当前最可能的主要问题是什么。
7. 家长修正并确认当前问题理解。
8. 系统将家长的期待转成可观察目标。
9. 必要时邀请孩子参与，或保留家长转述及未参与状态。
10. 系统提出方案草案。
11. 经过规则、来源、适用性、安全等必要检查后，由家长确认方案版本。
12. 家庭开始执行。
13. 系统在约定节点收集反馈；有真实授权渠道时可以主动提醒，没有则依靠站内待办和主动返回。
14. 正式复盘执行和结果。
15. 根据证据：
    - 继续；
    - 降低或调整方案；
    - 重新评估；
    - 暂停；
    - 转介；
    - 进入维护。
16. 达到稳定条件后结束本轮。
17. 后续复发时关联旧个案重新开始，不覆盖旧结果。

### 5.2 必须支持的非理想路径

V1 必须能真实处理：

- 当前并不需要干预；
- 信息不足；
- 多方说法冲突；
- 孩子拒绝参与；
- 家长拒绝家庭合约形式；
- 方案做不到；
- 执行失败；
- 没有改善；
- 情况恶化；
- 家长暂停；
- 用户退出；
- 无法联系；
- 模型失败；
- 通知失败或结果未知；
- 发现当前主要问题不是数字使用；
- 出现安全风险；
- 需要外部现实支持。

不能只有“成功闭环”的 happy path。

## 6. 个案状态与结果

### 6.1 个案状态

V1 至少支持：

| 状态 | 含义 |
|---|---|
| OPEN | 正在推进 |
| WAITING | 等待必要信息、参与、真实复核或必要条件 |
| PAUSED | 用户或系统已暂停普通推进 |
| LOST_CONTACT | 按规则确认失访 |
| SAFETY_HOLD | 当前优先处理安全问题 |
| CLOSED | 本轮个案结束 |

### 6.2 阶段

阶段与状态分开。

阶段包括：

```text
INTAKE
ASSESSMENT
GOALS
PLANNING
EXECUTION
REVIEW
MAINTENANCE
```

暂停后仍然知道：

> 暂停前处于哪个阶段。

### 6.3 结果

结果独立记录：

```text
IMPROVED
NO_CHANGE
WORSENED
UNKNOWN
```

没有反馈：

> **UNKNOWN**

不是“改善”。

### 6.4 结案原因

至少区分：

- 稳定改善；
- 无需干预；
- 用户主动退出；
- 超出 V1 范围；
- 已确认完成外部服务衔接。

结案原因不等于结果。

## 7. 目标、方案、任务、反馈与复盘

### 7.1 基线

基线应根据专业规则按需了解：

- 数字使用用途；
- 时长及其来源；
- 停止使用困难；
- 工作日/休息日差异；
- 睡眠；
- 学习与必要活动；
- 冲突；
- 情绪担忧；
- 线下活动；
- 家长既往做法及效果。

不要求每一项都必须量化。

不以统一小时数判断“沉迷”。

### 7.2 目标

每个当前个案一个主要目标。

目标必须：

- 能观察；
- 有基线；
- 有观察窗口；
- 有保护条件；
- 包含家长自身行动；
- 不把“让孩子听话”直接作为可执行目标。

### 7.3 方案

方案至少包含：

- 当前问题理解及不确定性；
- 目标；
- 为什么选择这些行动；
- 家长行动；
- 必要家庭协商；
- 孩子任务（仅在有适当参与依据时）；
- 反馈节点；
- 复盘节点；
- 可能阻力；
- 调整条件；
- 暂停条件。

家庭合约只是可选形式。

### 7.4 首批任务

首次方案建议控制在：

> **1—3 个优先任务**

这是默认交互原则，不是永久专业硬阈值；专业规则可根据情况调整。

每个任务说明：

- 谁负责；
- 做什么；
- 什么情况下做；
- 如何观察；
- 遇到困难怎么办。

### 7.5 反馈

反馈不只问：

> “做没做？”

还需要允许记录：

- 完成程度；
- 未执行原因；
- 障碍；
- 实际变化；
- 家庭成员反馈；
- 新风险；
- 不知道；
- 不愿回答。

### 7.6 复盘

复盘必须比较：

> 基线 → 方案 → 实际执行 → 结果。

需要区分：

- 执行不足；
- 方案不适合；
- 信息原来判断错误；
- 出现新主要问题；
- 实际有所改善；
- 重要不利变化。

例如：

> 屏幕时间下降，但睡眠更差、冲突明显升级。

不能直接评价成：

> “方案成功”。

## 8. 持续跟踪

持续跟踪是 V1 核心能力，不是以后再加。

每份生效方案必须定义：

- 下一次反馈或复盘节点；
- 当前采用主动返回还是授权提醒；
- 当前可履约渠道；
- 节奏；
- 撤回方式。

具体频率：

> 根据问题、阶段、家庭负担和专业规则决定。

不统一规定所有家庭“两天一次”或“一个月一次”。

提醒只是：

> 促成用户回来提供真实反馈的工具。

提醒发送成功：

> 不等于用户收到、执行或改善。

用户拒绝可选提醒：

> 不自动失去使用方案的资格。

---

## 9. 长期家庭档案

V1 从第一天建设长期档案。

至少长期保留：

- 重要家庭及人物信息；
- 历史问题；
- 关键陈述及来源；
- 重要事件；
- 历史目标；
- 历版方案；
- 任务；
- 执行；
- 复盘；
- 有效和无效的方法；
- 结果；
- 转介；
- 纠错关系。

两年、五年后回来：

> 系统仍应能够在当前授权和当前问题需要范围内找回相关历史。

长期档案不等于：

> 把所有聊天原文每次全部喂给模型。

## 10. 隐私、授权和纠错

### 10.1 数据使用必须有用途边界

至少区分：

- 当前服务；
- 模型处理；
- 普通提醒；
- 人工回访；
- 跨成员共享；
- 其他未来用途。

不能用一次总授权覆盖所有用途。

### 10.2 跨成员信息

V1 基本原则：

> 不能因为“AI 看过了”就把一个人的私人信息用于另一个人的定制建议。

如果本人明确允许：

> “可以用于优化共同计划，但不要告诉家长原话或来源”

系统可以按授权生成用途受限的派生信息。

如果没有授权：

> 即使已经脱敏，也不能自动跨成员使用。

### 10.3 纠错

用户有权：

- 查看；
- 更正；
- 对争议信息保留争议；
- 请求导出；
- 请求删除。

更正后：

> 后续摘要、建议和方案不能继续把旧错误当真。

### 10.4 删除

当前产品承诺维持：

- 主动删除申请经核验范围后，**7 天内清除应用在线数据**；
- 恢复备份滚动保留 **50 天**；
- 删除执行状态必须真实显示。

7 天不是聊天自动保存期限。

备份 50 天也不等于家庭资料只能保存 50 天。

具体数据库、备份、索引和派生数据传播方式由技术设计定义。

---

## 11. Safety 与转介

V1 不是危机救援产品，但必须具备：

> **识别风险 → 中断普通流程 → 展示已审核的现实支持路径 → 正确记录和转介**

安全检查不是注册时一次完成。

在：

- 新输入；
- 反馈；
- 复盘；
- 方案重大变化；
- 恢复服务；

都可能重新触发。

当出现高风险时：

- 普通建议停止；
- 普通任务推进停止；
- 普通提醒按规则停止；
- 安全信息优先；
- 不承诺不存在的真人即时响应。

安全状态不能因为：

> 用户下一句说“我没事了”

或：

> 模型下一次判断成低风险

就自动解除。

---

## 12. AI 用户体验要求

产品只规定用户可观察结果，不锁死内部技术。

V1 要求：

1. 用户提交成功后，应快速看到明确的处理状态。
2. 用户可以离开页面，回来后继续查看当前真实状态。
3. 未经过必要权限、专业规则和安全检查的内容不能作为正式建议释放。
4. 普通低风险交流可以采用受控渐进展示或流式体验，但不得让未通过关键校验的行动建议提前生效。
5. 高风险或高影响内容可以先完成检查再整体释放。
6. 模型失败、超时或结果过期时必须真实显示，不生成假答案。
7. 用户的新风险输入不能被旧 AI 任务阻塞。
8. 重试不能重复保存同一用户事实或重复启用方案。

具体 Decision / Response 协议与流式实现见 06。

## 13. 页面职责

V1 用户侧至少覆盖以下用户任务，可合并视觉页面，但不能删除职责：

| 编号 | 用户任务 |
|---|---|
| U01 | 服务范围、开放状态与登录 |
| U02 | 服务说明、授权与隐私 |
| U03 | 家庭及必要人物资料 |
| U04 | 当前个案总览 |
| U05 | 了解与交流 |
| U06 | 问题理解与目标 |
| U07 | 方案与版本 |
| U08 | 任务与反馈 |
| U09 | 复盘与调整 |
| U10 | 维护、结案与历史 |
| U11 | 提醒与反馈设置 |
| U12 | 我的资料、纠错、导出与删除 |
| U13 | 安全支持与转介 |
| U14 | 孩子受邀参与 |

内部后台只建设完成 V1 所必需的：

- 专业内容审核；
- 风险和异常处理；
- 权利请求；
- 必要质量抽查；
- 实际人工事项；
- 基础开放与成本观察。

不为了“后台完整”提前建设机构 CRM。

## 14. V1 需求清单

以下 40 项继续作为 V1 需求唯一编号，便于 06 逐条映射。

### 14.1 进入、判断与目标

## 15. V1 成功判断

V1 不以：

- 页面做完；
- AI 能聊天；
- 方案生成成功；
- 通知发出；
- 用户说“感觉不错”；

作为产品成立。

真正需要验证：

1. 家庭能完成问题判断；
2. 能形成实际可执行方案；
3. 家庭真的执行；
4. 系统能按约持续跟踪；
5. 失败后能真实复盘和调整；
6. 能保留未知、恶化、退出、失访和转介；
7. 多个真实家庭出现可验证、可持续的改善案例；
8. 没有未解决的严重安全、隐私和越权问题；
9. 单家庭交付成本能够承受。

小样本验证不能宣传成：

> “已经证明普遍有效。”

## 16. 真实服务放行前必须核实

以下均不能因为文档完成而视为已经通过：

- 数字使用专业包及安全规则已由合适责任人审核；
- 小程序 AppID、类目、发布状态和登录真实可用；
- 实际通知渠道和授权能力已验证；
- 模型供应商的账户、地域、数据处理条款和真实 model ID 已验证；
- 权限隔离和越权测试通过；
- 数据导出、纠错、删除和恢复演练通过；
- 安全资源信息真实有效；
- 普通闭环、异常路径、模型失败、并发、通知未知状态均通过测试；
- 实际开放范围与系统承载能力匹配。

## 17. 与其他文档的边界

### 01 / 03 决定

> 小树荫是什么，以及未来去哪里。

### 本文 04 决定

> **V1 必须做什么，以及用户能观察到什么。**

### 05 决定

> 为了长期支撑 V1—V5，技术地基应该怎样设计。

### 06 决定

> V1 这一次具体怎样实现 04，同时遵守 05。

如三者发生冲突：

> **产品范围以 04 为准；技术不得擅自扩大 V1。**

但技术发现安全、隐私或现实不可履约问题时：

> 必须回到产品文档明确修订，而不是在代码里偷偷改变产品行为。
