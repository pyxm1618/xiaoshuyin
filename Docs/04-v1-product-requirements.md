# 第一层：Common Problem-Solving Core

## 0. V1 的唯一正确理解

## 0.1 V1 不是一个“手机问答功能”

V1 要证明的不是：

> AI 能不能回答家长几个关于手机的问题。

而是：

> **小树荫能不能依托一套可复用的问题解决系统，把一个真实家庭的儿童青少年数字使用困扰，从发现与判断，一直推进到目标、方案、执行、持续跟踪、复盘调整，并获得真实改善或正确退出。**

因此：

> **V1 = Common Problem-Solving Core + Digital Use Scene + Production-Ready Product Boundaries**

其中：

- Common Problem-Solving Core 负责所有未来场景都要复用的 Case、证据、目标、方案、任务、执行、反馈、复盘、结果、权限、安全和长期档案；
- Digital Use Scene 负责“手机 / 平板 / 电脑 / 游戏机等数字使用问题到底怎样判断、怎样选择解决路径、怎样执行和怎样评价”；
- Product Boundaries 负责真实服务必须具备的授权、隐私、持续跟踪、安全、正确退出、错误状态和真实验证。

三者缺一，V1 都不完整。

## 0.2 V1 与未来 10、20、50 个场景的关系

V1 不把系统写死成“手机系统”。

未来增加厌学、亲子冲突、学习、情绪、青春期、社交等场景时，应复用同一套 Common Problem-Solving Core，并为每个正式场景增加自己的 Scene Package。

未来新场景原则上只新增或扩展：

- Evidence / Eligibility；
- Assessment；
- Problem Formulation；
- Intervention；
- Goal；
- Plan；
- Follow-up；
- Review；
- Maintenance / Closure；
- Safety；
- Professional Knowledge。

不应为了每增加一个场景，重新建设 Case、Memory、Consent、Plan、Task、Follow-up、Review、Outcome 和 Safety 等通用机制。

## 0.3 V1 的产品完成标准

V1 不是在以下任一时点完成：

- 页面开发完成；
- AI 可以聊天；
- Assessment 问完；
- 生成了一份方案；
- 用户点击“开始执行”；
- 发出了一条提醒；
- 完成了一次任务；
- 用户说“感觉不错”。

V1 的服务闭环是：

~~~text
进入
→ 描述问题
→ 收集必要证据
→ 判断当前主要问题
→ 形成问题理解
→ 确认目标
→ 选择适用的干预路径
→ 形成可执行方案
→ 执行
→ 持续跟踪
→ 收集真实反馈
→ 复盘
→ 继续 / 调整 / 重新判断
→ 维护
→ 稳定改善 / 无需干预 / 退出 / 超范围 / 外部支持
~~~

出现信息不足、安全风险、用户拒绝、无法执行、没有改善、恶化或失联时，必须保留真实状态，不能为了走完流程伪造“完成”。

## 1. V1 用户、场景与边界

## 1.1 主要用户

V1 的主要发起用户是：

> **正在面对未满 18 岁孩子的数字使用困扰，并且不知道应该怎样处理的家长。**

V1 面向中文家庭，主要服务国内用户；不因为产品定义把港澳台家庭概念性排除，但真实登录、通知、现实支持资源和合规能力必须按实际可用范围显示。

V1 用户主端是现有微信小程序“小树英助手”。家长主账号在小程序发起和推进 Case；获邀孩子在当前问题的有限参与范围内进入。V1 不要求为了架构完整再建设一套面向家庭的独立 Web 产品。

数字使用包括但不限于：

- 手机；
- 平板；
- 电脑；
- 游戏机；
- 与互联网、游戏、短视频、社交、娱乐或必要学习联系相关的设备使用。

不设置未经专业依据验证的统一最低年龄。

## 1.2 参与原则

V1 采用：

> **家长可以独立开始；孩子按问题需要参与。**

孩子可以：

- 接受邀请；
- 查看明确共享给自己的内容；
- 表达本人意见；
- 对本人相关目标或任务表态；
- 提交本人反馈；
- 拒绝参与；
- 中途退出。

不要求爸爸、妈妈、孩子或祖父母全部注册。

未注册成员可以通过家长转述被记录，但：

> **转述永远不能自动升级为本人确认。**

## 1.3 V1 正式服务范围

V1 可以在“当前数字使用问题”范围内处理：

- 数字使用行为；
- 作息和睡眠；
- 必要学习与联系；
- 线下活动与行为替代；
- 家长行为；
- 家庭成员在当前问题上的一致性；
- 与当前问题直接相关的沟通和冲突；
- 当前问题中的需求、动机、能力、阻力；
- 共同规则或行动计划；
- 执行障碍；
- 持续跟踪；
- 阶段复盘；
- 方案调整；
- 维护和复发；
- 必要的孩子轻量参与。

这些内容只在“服务当前数字使用问题”所需范围内处理。

例如：

> 睡眠可以是当前手机问题的重要影响因素和行动目标。

但 V1 不因此自动提供一个完整的独立睡眠治疗产品。

## 1.4 V1 不提供

V1 不建设：

- 多个主要问题同时执行；
- 完整家庭多人私人空间；
- 其他儿童问题的完整独立干预流程；
- AI 心理或精神疾病诊断；
- 危机救援服务；
- 实时家庭调停；
- 实时语音咨询；
- 跨家庭相似案例推荐；
- 行为预测；
- 支付、订阅、退款体系；
- 机构平台；
- 全年龄服务。

如果在手机场景中发现：

> 当前真正主要的问题并不是数字使用，

系统必须停止机械执行手机方案，并进入重新判断、正确退出或现实支持路径。

## 2. Common Problem-Solving Core：V1 通用问题解决内核

本节定义未来所有正式 Scene 都应复用的产品级业务合同。

---

## 2.1 一个家庭当前只推进一个主要 Case

一个家庭可以同时存在多个候选问题，例如：

- 数字使用；
- 厌学；
- 情绪；
- 严重亲子冲突；
- 父母意见不一致。

但当前最多只有一个主要 Case 进入普通执行主线。

候选问题可以被记录，但不得偷偷开启第二条正式执行线。

需要切换主要 Case 时：

1. 说明为什么建议切换；
2. 保留原 Case 的问题理解、目标、方案、执行和结果；
3. 说明旧任务和提醒如何处理；
4. 由有权用户确认；
5. 完成切换后再启动新主线；
6. 安全状态不能通过“切走 Case”规避。

---

## 2.2 证据、陈述、事实和假设必须分开

任何用于判断的信息必须保留：

- 涉及谁；
- 谁提供；
- 发生或观察时间；
- 记录时间；
- 来源类型；
- 原始内容或引用；
- 是否已确认；
- 当前是否仍有效；
- 是否存在冲突。

至少区分：

- 本人陈述；
- 家长观察；
- 家长转述；
- 其他成员转述；
- 手工录入的设备数据；
- 工作人员记录；
- AI 假设；
- 经相应来源确认的信息。

例如：

> 妈妈说“孩子每天玩六小时”。

系统首先得到的是：

> 妈妈关于孩子数字使用时长的陈述。

不是：

> 孩子每天客观确定玩六小时。

如果孩子说“两小时”，系统允许：

> **当前存在来源冲突，暂时无法确定。**

AI 不能自己挑一个更顺眼的数字升级为事实。

---

## 2.3 允许“不知道”

V1 必须区分：

- 已知；
- 不知道；
- 尚未收集；
- 明确拒绝回答；
- 不适用；
- 来源冲突；
- 已失效。

不能把：

- 空值写成“否”；
- 未回答写成“0”；
- 家长不知道写成确定答案；
- AI 推测写成用户事实。

---

## 2.4 Case 生命周期

正常阶段至少包括：

~~~text
INTAKE
ASSESSMENT
PROBLEM_FORMULATION
GOALS
PLANNING
EXECUTION
REVIEW
MAINTENANCE
CLOSED
~~~

阶段表示：

> 正常的问题解决工作进行到哪里。

服务状态另外保存，至少包括：

~~~text
OPEN
WAITING
PAUSED
LOST_CONTACT
SAFETY_HOLD
CLOSED
~~~

阶段和服务状态不能混成一个字段。

例如：

> PAUSED + EXECUTION

表示：

> 原来正在执行，但当前暂停。

---

## 2.5 每个 Case 都必须有 Problem Formulation

Assessment 不是把问题问完就结束。

进入 Goal 前，系统必须形成一份可供用户理解和纠正的：

> **当前问题理解 / Problem Formulation。**

至少说明：

- 当前最重要的已知信息；
- 信息来源；
- 当前最可能的主要问题；
- 关键影响因素；
- 当前仍然不知道什么；
- 是否存在来源冲突；
- 为什么继续当前 Scene；
- 哪些替代解释目前不能排除；
- 哪些情况会要求重新判断或退出当前 Scene。

Problem Formulation 必须允许用户：

- 纠正；
- 补充；
- 不同意；
- 暂不确认。

没有足够依据时允许：

> 暂时无法判断。

---

## 2.6 Goal 合同

每个当前 Case 有一个主要目标，可以有多个共同服务于它的行动目标。

正式 Goal 至少包括：

- 当前基线；
- 希望发生的变化；
- 怎样观察变化；
- 观察窗口；
- 关键保护条件；
- 家长自身行动；
- 必要时孩子或其他成员的真实责任来源；
- 复盘节点。

不能把：

> “让孩子听话”

直接作为合格 Goal。

也不能只定义：

> “每天少玩两个小时”

却完全不说明睡眠、必要学习联系、家庭冲突或其他重要保护条件。

---

## 2.7 Plan 合同

正式 Plan 至少包含：

- 当前 Problem Formulation；
- Goal；
- 为什么选择这些 Intervention；
- 家长行动；
- 必要家庭协商；
- 孩子任务及其来源；
- 每项任务的责任人；
- 执行情境或时间；
- 观察方式；
- 预计阻力；
- 遇到阻力怎么办；
- Follow-up 节点；
- Review 节点；
- 调整条件；
- 暂停条件；
- Safety 条件；
- 当前 Plan Version。

方案草案、待确认方案、生效方案、已替换方案、暂停方案必须分开。

---

## 2.8 Task 与 Execution

Task 不是抽象建议。

每项任务至少说明：

- 谁负责；
- 做什么；
- 什么时候或什么情况下做；
- 需要谁配合；
- 如何判断是否执行；
- 遇到困难怎么办。

Execution 至少允许：

- 未开始；
- 进行中；
- 部分完成；
- 完成；
- 未执行；
- 暂停；
- 取消。

逾期不自动等于失败。

---

## 2.9 Follow-up

每一份生效 Plan 都必须存在：

- 下一次反馈或复盘节点；
- 当前需要用户主动返回，还是存在真实授权提醒；
- 当前实际可用渠道；
- 提醒频率和安静时间；
- 撤回方式。

提醒的意义是：

> 促成用户回来提供真实反馈。

提醒成功发送不等于：

- 用户收到；
- 用户执行；
- 结果改善。

没有提醒许可时，适用的 Plan 仍可以执行。

---

## 2.10 Feedback

Feedback 不能只问：

> 做了吗？

至少允许收集：

- 完成程度；
- 没做的原因；
- 执行中发生了什么；
- 哪个成员怎样反应；
- 实际变化；
- 新阻力；
- 新担忧；
- 新风险；
- 来源；
- 对应 Plan Version；
- 不知道；
- 不愿回答。

---

## 2.11 Review

正式 Review 必须比较：

> 基线 → Problem Formulation → Goal → Plan → 实际执行 → 实际变化 → 保护条件。

Review 需要判断至少这些可能：

- 主要是执行不足；
- 任务负担过高；
- 家庭成员没有形成必要配合；
- Intervention 选择不合适；
- 原 Problem Formulation 不完整；
- 出现新的主要问题；
- 有改善；
- 无明显变化；
- 恶化；
- 证据不足。

Review 不能只因为一个指标变好就宣布成功。

例如：

> 数字娱乐时长下降，但睡眠更差、冲突大幅升级。

不能直接记录为“方案有效”。

---

## 2.12 Review 后允许的动作

Review 后只能进入有依据的下一步：

- CONTINUE：继续当前 Plan；
- ADJUST_PLAN：调整并生成新 Plan Version；
- REASSESS：回到 Assessment / Problem Formulation；
- WAIT：等待必要信息或参与；
- PAUSE：暂停；
- MAINTENANCE：进入低强度维护；
- OUT_OF_SCOPE：当前产品不适合继续；
- REFERRAL：进入现实支持衔接；
- SAFETY_HOLD：安全中断。

实质调整必须形成新版本，不能静默修改旧 Plan。

---

## 2.13 Outcome 与 Closure 分开

Outcome 至少包括：

~~~text
IMPROVED
NO_CHANGE
WORSENED
UNKNOWN
~~~

Closure 原因至少区分：

- STABLE_IMPROVEMENT；
- NO_INTERVENTION_NEEDED；
- USER_WITHDREW；
- OUT_OF_SCOPE；
- EXTERNAL_HANDOFF_COMPLETE。

因此：

> Case 已关闭 ≠ 问题改善。

用户退出或失联也不能被统计成改善。

---

## 2.14 Maintenance 与复发

达到阶段性改善后，可以进入 Maintenance。

Maintenance 应定义：

- 当前稳定条件；
- 需要继续保持的关键行为；
- 低频观察节点；
- 复发信号；
- 重新进入 Assessment / Planning 的条件。

复发不能覆盖上一轮结果。

需要新一轮正式服务时：

> 建立与历史 Case 关联的新一轮 Case 或明确的新服务轮次。

# 第二层：Digital Use Scene — 原始流程忠实版

## 忠实性合同

以下内容来自用户提供的原始《沉迷手机_需求文档》，按原文结构转为 Markdown 以便开发和版本追踪。

**本节不是摘要。**

开发时必须按以下原则理解：

- 原模块编号保留；
- 原前置条件保留；
- 原用户输入 / 判断保留；
- 原分支去向保留；
- 原输出保留；
- 原记录要求保留；
- 原先明确可并行的任务继续并行；
- 原先明确按时间线推送或允许用户主动进入的关系继续保留；
- 后文对各目标、工具、合约、沟通、可行性和帮助内容的详细展开，均属于对应模块的需求上下文；
- 即使某条专业结论后续被质疑，也先保留原流程位置；调整必须通过后续显式产品决策完成，不能由开发者或 AI 自行改写。

## 原始需求正文镜像

如何帮助孩子制订合理的“使用手机的计划”

**孩子的年龄范围**：小学至高中6-18岁

**问题描述：**很多学生需要使用手机辅助学习、查询信息、提交作业、跟父母保持联系或者与同学交流，但是同时花费过多的时间使用手机刷视频玩游戏。家长没有办法完全不给他们用手机，也没有办法限制孩子使用手机时间，因为手机的问题产生亲子关系冲突。

**背景知识**：心理学家和教育学家建议6-12岁孩子每天使用手机不超过1小时。12-18岁的青少年每天使用手机不超多2小时。

**解决问题的方法**：

1.  建立家庭联盟

2.  制订手机使用合约

**心理咨询的理论和方法：**

X“讲道理”（啰嗦、唠叨、反复说）是没有用的

X完全禁止是没有用的

X 很多育儿/家庭教育原则是模糊笼统的，家长即使理解了，还是不知道怎么去操作

保证孩子的睡眠时间

运动和兴趣爱好

应对焦虑情绪

改善拖延行为

自尊心：内在动机

奖励机制：外在动机

家长和孩子之间的信任

家长的一致性：夫妻之间达成一致，父母和祖父母之间达成一致

家长行为的一致性；言行一致，坚持原则

## 背景知识

## 使用手机的建议

2岁之前的孩子不要使用手机

2-11岁每天使用不超过1小时

12-18岁每天使用不超过2小时

这些时间指的是一周内平均每天使用手机的累计时长可以根据孩子的实际情况进行调整

为帮助孩子形成健康的使用手机的习惯，家长应该尽早在孩子一开始用手机的时候就制订这些规则：

家里的某些区域不能用手机（比如洗手间，或者餐桌上），适用于所有家庭成员

某些时间不能用手机（比如吃饭的时候）

每周抽出一整天的时间不用手机

有目的地使用手机，而不是随随便便地拿在手里玩，不要一边看电视一边玩手机

不要把手机声音作为背景音（一边播放手机视频一边做其他的事情）对于孩子来说，不要一边学习一边用手机放音乐，如果一定要放音乐，可以使用专门的音乐播放器

不要躺在床上看手机

对于那些时不时就要看一下手机的人来说，可以尝试这种方法：工作或者学习的时候使用一个计时器，每工作50分钟之后可以专门地来看手机5-10分钟

如果你的孩子刚刚开始使用手机，跟孩子制订以上的规则比较容易，你可以选择其中的几条。作为家长，一定要自己亲身示范，不能只对孩子提出要求，而自己完全不理会上述规则；

如果你的孩子已经形成了他使用手机的习惯，现在要想改变可能不太容易，请参考我们在这个专题里面提供的帮助孩子养成健康地使用手机的习惯的方法

请避免以下方法：

强制没收孩子的手机（没收手机不是完全不行，但是在没收之前一定要先和孩子讲好，出现什么样的情况就会没收手机，如果真的出现了这种情况，再去没收）

强制删除孩子手机里的软件、游戏或者其他内容

不停地唠叨孩子，要求孩子控制使用时间

关于使用手机的隐私问题：

家长需要跟孩子建立信任，跟孩子约定好，不去查看他的手机，但是有例外的情况，比如出现异常的消费，或者是孩子交了社会上的不可靠的朋友，这些要跟孩子事先说好

使用手机的安全问题：

不能把以下信息发给不熟悉的人或者学校以外的人：家庭住址、电话、银行信息、个人照片、个人视频

## 情绪问题

孩子的情绪和家长的情绪有可能相互影响

情绪是人际关系的信号，孩子的情绪有问题往往代表亲子关系存在问题

家庭成员之间的相互支持对于修复情绪问题至关重要。

情绪是一种包含了想法、感受和行为倾向的综合体，很多人都不能准确地表达自己的情绪。

有些家长会鼓励孩子说出自己的情绪，认为只要孩子把情绪说出来，他的问题就能解决了，这种做法不一定有效果。对于小孩子来说他可能说不清楚，过于青春期孩子来说，他可能不愿意跟家长说情绪，或者说得很敷衍（“就是烦”）

家长可以有意识地练习自己对情绪的觉察力，包括对自己情绪和对孩子的情绪的觉察。可以参考我们的情绪觉察的专题

最简单的处理情绪的原则有这些：

多听，少说：不要急于扭转对方的负面情绪，不要急于改变对方的想法。比如说，当你告诉对方，你的想法不对，没有必要这么想，哪怕你说的都对，但是对方会感觉到你没有理解他的情绪，进而会对你反驳（狡辩）。这个时候你们双方讲道理是讲不清楚的，因为深层的原因根本就不是一个讲道理的问题，而是一个情绪的问题。

可以教别人如何思考，但是不要教别人如何去感受，不要告诉孩子什么样的感受是对的，什么样的感受是错的，因为感受没有对错之分。

沟通技巧：不需要直接询问别人的感受，可以询问对方的想法，但是在听的时候一定要去理解对方的感受，在理解对方感受的基础上再去考虑对方说得对不对。

在向别人表达自己的时候，不要过于强调自己的想法，可以尝试着多向对方表达自己的感受

家长要特别特别留意孩子的两种感受：一种是愤怒感，一种是内疚感。家长往往希望/鼓励孩子有内疚感（认为孩子内疚了就会改），而不希望孩子有愤怒感（脾气差，没涵养）。**这是非常非常错误的！！适当地表达愤怒有保护的作用，如果一个孩子长期有内疚感而压抑愤怒感，就会造成抑郁。家长要尽量避免让孩子产生内疚感，而当孩子表达愤怒感的时候，家长一定要认真去倾听，了解孩子到底是因为什么而愤怒，不要简单地指责，不要认为愤怒是错误的。愤怒没有错，错的可能是表达愤怒的某种方式。**

## 亲子冲突

亲子冲突往往发生在孩子的青春期，但是目前这个时间已经有很大的提前，家长把冲突的原因归结为孩子的叛逆。其实没有经历过叛逆期的孩子是没有真正成长起来的，有的孩子貌似没有叛逆期，但是他们可能在进入成年、中年，甚至老年的时候出现叛逆期。

叛逆的本质是摆脱家长的控制，获得自己的自主性，这归于一个人的成长非常有必要。

那些灵活的家长改变控制方式，孩子比较顺利地度过叛逆期。

一些控制非常紧的家长貌似控制得很好，孩子很听话，但是孩子的人格发展留下了隐患。

对于另外一些控制非常紧的家长，孩子也在争夺自主权，亲子冲突就会很激烈，其实未必是坏事

解决方法：家长一定要给与孩子自我成长的空间。

与孩子保持一定的距离，随着孩子年龄越来越大，划定必要的底线，然后允许孩子在最大可能的范围内自己做决定，自己做选择

解决亲子冲突问题，家长一定要调整自己的情绪。很多家长感到迷茫、不知所措、焦虑担忧，然后认为孩子的行为是自己情绪的根源，**这种认知是错误的。因此，家长希望通过改变孩子的行为来改变自己的情绪，这种方法也是错误的。**

反过来，如果家长调整好自己的情绪，孩子的行为反而可能越来越好。

## 家庭手机使用联盟

家长和孩子一起解决问题，为孩子提供情绪的支持和行为方面的指导，制订科学的日常行为规划

主要的原则：

家长以身作则

正面帮助孩子形成更多的健康行为习惯

家长花更多时间和孩子相处

获益：

帮助孩子提升情绪管理能力、应对压力的能力和自律能力

提升亲子关系

帮助孩子养成健康的习惯和生活方式

“联盟”代表一种合作关系，取代了管理与被管理，控制与被控制等不利于孩子发展自主性的互动模式

“联盟”可以有效地为孩子提供情绪支持，帮助孩子发展自尊心和自律能力

关于“信任”

要形成有效的“联盟”，家长需要给与孩子充分的信任。但是，很多家长认为孩子的自律能力差，答应下来的事情也常常办不到，因此他们作为家长不得不主动约束和管教孩子。需要给这些家长提供三个建议：

1.  家长管理的越多，孩子的自我管理就越少。家长认为自己“管得多”是问题的结果，但事实上它也是问题的原因，这个原因和结果不断地循环，而问题会变得越来越严重。因此家长需要找到一个合适的契机，打破这种负面的循环。

2.  表达对孩子的信任需要耐心，给孩子一定的空间，允许孩子犯错误，在错误中获得经验，也要尽量创造条件让孩子取得成功，从成功中获得动力。要为孩子创造成功的条件，就一定要准确地理解孩子的能力。

3.  家长需要从一个新的角度对孩子的能力进行评估。很多家长从自己的角度出发，认为自己对孩子的期待完全符合孩子的能力，孩子应该做到。但是如果从孩子的角度出发，能力包括注意力、意志力、情绪调节的能力、自尊心、内在动机、学习风格等。 所有这些因素都是复杂的， 很对家长不能对这些因素做出具体详细的评估，因此很难说他们真正了解孩子的能力。

### 建立家庭手机使用联盟的原则和注意事项

1.  为了帮助孩子养成良好的使用手机的习惯，所有家庭成员需要共同参与、互相配合。达成“一致”意见比选择“正确”的意见更重要。哪怕最终的选择（决定）在你看来不是最好的，但是为了达成一致，你也可以先做出让步和妥协。这一点非常重要。

2.  家长需要处理好自己的情绪并且为孩子提供情绪支持。

3.  家长需要规范自身使用手机的习惯

4.  家长需要用协商的方式或者孩子的同意和认可，而不是用命令的方式强制孩子执行

5.  对于那些主要由妈妈负责管教孩子，爸爸忙于工作的家庭，爸爸需要尽可能的参与，至少需要了解这个家庭联盟并且配合其他人。祖父母也需要了解和配合。

可以尝试的一些家庭规则：

在家庭的某些区域，手机不能进入。比如洗手间，厨房，或者餐厅

在某些场合，所有人都不能使用手机，比如餐桌上吃饭的时候，但是如果有来点可以离开餐桌接电话

每周抽出一个特定的时段，比如每周半天或者一天时间，全家人不用手机，接电话除外

用手机的时候就专门使用手机，不要一边玩手机一边做其他的事情

1.  情绪是沟通的基础。家长不仅要关注表面上的情绪，还要关注表面情绪背后的深层情绪。比如说家长和孩子商量事情的时候，孩子表现的不耐烦。不耐烦只是表面的情绪，更深层的可能是孩子对困难的担忧。解决的方法是多听少说，尽量让孩子多说。孩子如果不愿意说，通常是处于对家长的不信任，认为说了也没有用。

    4）家庭成员需要协调一致。达成一致比争论谁对谁错更重要。无法达成一致时可以暂时搁置，以后再说。

    5）保持言行一致，保持情绪的稳定，如果家长经常受到自身情绪的干扰，可以参考我们的情绪模块。

    6）说到做不到的后果：如果家长答应了孩子一些事情，事后又变卦，这还不如答应，如果做不到就不要承诺，在做出决定之前要充分评估自己能否做到，以及如何去做，具体的措施，越具体越好。

    一码事归一码事，不要追加条件。例1，家长答应了孩子写完作业就可以玩手机，孩子写完作业了，家长一看时间还早，就要求孩子先做家务，做完家务再玩手机。这就是典型的说到没做到。“做家务”是一个追加的条件。

    例2：家长答应孩子每天背诵半小时语文，奖励暑假旅游。孩子坚持了一学期每天背诵，但是期末考试语文成绩不好，家长一气之下取消了旅游。这是典型的说到没做到。如果孩子做到了，而家长一开始的时候就没有提出把考试成绩作为条件，那么就应该兑现奖励。

    注意：家长对孩子提出要求时，要尽量具体到行为，而不要把成绩（结果）作为要求。因为结果有不确定性，而行为有更多可控性。结果和好的行为习惯不一定有必然关联（有的人会作弊投机取巧），但是具体的行为是养成好的行为习惯的基础。

家长和孩子一起制订一份关于如何使用手机的合约，以文字的方式写出来

原则：

要求孩子主动参与合约的制订

父母在这个问题上要达成一致意见

父母要言行一致，言出必行

获益：

培养孩子的自主性，提升内在动机，预防和改善拖延

提升孩子和家长之间的信任感

## 内在动机

内在动机是行为的真正的驱动力，内在动机强烈的人更容易获得成功，实现真正的自我价值，有更强的自信心和自律能力

提升内在动机需要满足孩子的三种需求

1.自主性：

允许孩子自己做决定

邀请孩子参与决策和计划的制订

总是给孩子提供多种选择，而不是只有一个选项。选择本身就是在发挥自主性。

2.胜任感：

要考虑问题的难度，难度太高会让孩子产生挫折感，进而拖延，适当的难度能够让孩子获得成功体验，成功体验是学习的一个重要途径，只有获得成功体验，才能真正学会一种技能

3.关系：

家长和孩子的关系：信任感、情感支持、尊重、适当的空间和自由

信任感：允许孩子犯错误，犯错误之后不要指责或贬低嘲笑，而是鼓励孩子吸取经验，下次做得更好。（有时候孩子犯多次错误才能吸取教训，家长要耐心）

情感支持：允许孩子表达感受，当孩子表达感受的时候最好的应对方式是倾听和陪伴，而不是说教或者纠正。特别留意两种情感：愤怒感和内疚感

尊重： 让孩子自己管理自己的事情就是一种尊重

适当的空间和自由：亲子关系并不是越近越好，越亲密越好。孩子年龄越大，和家长的距离就会越远，不论是物理上的距离还是心理上的距离。家长一定要持续地体验孩子离自己越来越远的那种心理感受，这种感觉并不好受，家长一定要留意，这也是自我情绪调节的一部分。

## 亲子关系潜在问题

亲子关系潜在的问题主要是互动模式的问题。

问题型互动模式主要有这些：

1.  家长控制——孩子也控制：互相争夺、冲突

2.  家长控制——孩子回避：一方焦虑，一方压抑

3.  家长控制——孩子服从：表面没有问题，以后可能爆发

4.  家长回避——孩子控制：并不少见，表现为孩子以厌学、辍学、伤害自己、离家出走、结交不良朋友、诉诸语言或者肢体暴力等行为来要挟家长，而家长无所适从，不敢正面应对问题

5.  家长回避——孩子也回避：冲突紧张到一定程度，双方无法沟通；或者双方明明都知道问题所在，却不愿意正面应对

控制型家长：控制是一种心理和行为模式

控制的表现有这些：

给予孩子过多的照顾，要求孩子回报，当孩子不服从家长的意愿时，诉诸于孩子的内疚感

不允许孩子自己做决策，按照自己的理想为孩子规划好一切，塑造一个理想化的孩子而不是真实的孩子

不允许孩子犯错误，用贬低、斥责、惩罚的方式对待孩子的错误

制定严格和琐碎的标准

心理因素：

控制性的家长自身有不安全感、过高标准等心理因素，有自身违背满足的心理需求，因此控制是对自身需求的一种过度补偿，比如说家长自己未能实现的理想投射在孩子身上

控制带来的后果：

孩子缺乏自主性，进而缺乏内在动机，产生拖延行为，严重的会产生被动攻击行为

被动攻击：表面上同意或者配合，实际上拒不执行或者故意做错，造成反向的后果。

如果孩子总是在深夜玩手机，或者是因为用手机造成写作业拖延，影响了入睡时间，那么家长应该在帮助孩子控制手机使用时间的同时帮助孩子改善睡眠。

改善睡眠包括睡眠卫生教育和睡眠习惯养成两个部分。

#### 帮助选项（改善睡眠）

对常见的问题进行解答

1.  睡眠时间：

    学生8-9小时

    事实上很多学生不能睡够这么长时间，所以睡眠质量更加重要，睡眠质量主要以第二天的主观感觉来判断

2.  熬夜：

    是否一定不能熬夜？如果睡得晚醒的也晚的话其实没有关系，但是学生通常要起得早，所以不要熬夜。即使是周末也不要熬夜。应该保持一种7天入睡时间和起床时间都是一样的，不要在周末睡懒觉，如果确实需要补觉的，可以例外

3.  磨蹭、拖延导致睡觉迟//起床拖延

    家长尽量不要催促，可以使用任务评估表里面的维度和孩子一起来讨论这个问题。

### 运动。

对于成长中的孩子来说，建议每周进行中等强度的运动3-6次，每次30分钟以上。家长如果有时间，可以陪孩子一起运动。

#### 帮助选项（运动）

对常见的问题进行解答

运动可以是体育运动，也可以是游戏，也可以是孩子自主设计的活动，但是不能是棋牌桌游类

运动的目的是锻炼心肺能力，提高大脑供氧，增加多巴胺

运动能够让机体分泌多巴胺，让人更加愉悦

如果孩子不愿意自己运动，也可以考虑去报兴趣班，学习运动技能

#### 帮助选项（兴趣爱好）

对常见的问题进行解答

家长尽量不要自己给孩子设置兴趣爱好，可以鼓励孩子过去尝试，选择自己的兴趣爱好

如果孩子的兴趣爱好是“打游戏”怎么办？

可以鼓励孩子参与一些竞技性的游戏，可以是任何游戏，不一定限于电脑游戏，可以延伸到生活中的竞技游戏。如果孩子一定要把游戏作为自己的爱好，那么一定要包含两个因素（之一）：一个是设计（比如学习编程)，另一个是竞技

兴趣爱好和学习冲突怎么办？

通常只是表面上的时间冲突，如果合理规划时间，还是可以平衡的。

尽量避免让孩子因为学习放弃自己的兴趣爱好

如果兴趣爱好需要花很多钱怎么办？

家长在经济条件允许的情况下尽量满足孩子的兴趣爱好；不过经济条件不允许，帮助孩子培养其他爱好。不要用花钱支持孩子的兴趣爱好作为理由让孩子产生内疚感；也不要因为自己不能满足孩子的愿望而产生内疚感（很容易产生，需要自己调节）

如果孩子有和别人攀比的情况，没有必要纵容他，但是一定要创造条件，让孩子在某一些方面比较突出，有一些成绩，产生自豪感

#### 帮助选项（家务）

对常见的问题进行解答

是否可以让孩子通过做家务来赚零花钱？

可以。

注意，第一要提前跟孩子商量好零花钱如何支配。

2.  如果给孩子支付报酬，那么孩子做的家务一定是为整个家庭服务，也就是要帮别人做事情，如果只是洗自己的衣服收拾自己的房间，这些也可以算作做家务，但是不应该支付报酬

## 制订手机使用合约的准备工作

如果你购买电话或者手机上网服务，你会和通信商签一份合约。当你允许孩子拥有第一部手机的时候，你应该和孩子签订一份手机使用合约。

不同的是，你和通信商的合约里面所有的条款都是由通信商制订的，你能做的只是表达同意或者不同意

而当你和孩子签订一份手机使用合约的时候，你完全可以邀请孩子一起来指定条款。

如果你的孩子使用手机已经有一段时间了，甚至已经出现了一些不太好的行为，或者已经养成了一些不良习惯，你仍然可以和他一起签订一份手机使用合约，为时不晚。

你需要做的就是和孩子一起来制订这份合约的条款。如果你有几个孩子，那么你需要和每一个孩子分别签订合约。

如果你已经跟孩子签订过类似的“合同”，但是没有执行下去，那么大概率是因为你没有邀请孩子一起来制订合约的条款。

正误判断题：

1.  手机使用合约的每一个项目都要由家长和孩子一起来制订；

2.  制订手机使用合约以后，孩子必须做到合约里的要求，否则这份合约就失败了；

3.  家长不应该和孩子讨价还价，否则孩子就会不断提出不合理的要求；

4.  手机使用合约应该用来约束孩子，对家长不具有约束力；

5.  手机使用合约的期限越长越好

## 与孩子沟通

沟通原则：

沟通存在三个层面：情绪、认知和行为。

沟通的时候首先要明白沟通的目的，是为了安慰孩子的情绪，是为了改变他的认知，还是为了影响他的行为。

要明确目的，首先要做的就是理解对方的表达是在哪一个层次上，是为了表达情绪，是为了表达观点（认知），还是为了在行动层面和你沟通。

如果你听出了对方是有情绪的，那么一定要使用我们情绪调节任务里面的方法，不要否定对方的情绪，而是要表达你理解了对方的情绪。

不要在认知层面和对方争论，如果你想改变对方的想法，尽量拿出来试试、数据、科学依据、个人经历、寓言故事、真实案例等等。条件允许的情况下，也可以让对方去经历真实的结果（比如碰钉子）。不要用权威的身份、家长的身份要求孩子必须接受你的道理。

在行为层面，一定要和孩子制订一些“规则”或者原则，可以是某种约定，比如说手机使用合约。在行为层面，千万不要只是说教，提要求，而没有具体的规则。有时候，规则越具体越好。

## 选择工具

工具：

量尺

问题-需求转化工具

动机分解工具

自我调节工具

量尺：

两尺可以帮助我们找到解决问题的可能性。

量尺通常会问两个问题：

第一个：你觉得解决这个问题的可能性有多大？0分时可能性很小，10分是可能性非常大，0到10分之间你会打多少分？

第二个问题：

假如第一个问题给出的分数是4，我们可以接着来问：

为什么你选择了4分，而没有选择3分呢？

通过这一细微的比较，回答的人可以让心里面所考虑的“可能性”更清晰、更具体，也可以给自己提供更多的动力和希望。

但是如果第一个问题的答案是0分，（毫无可能性），我们接下来可以这样问：

我们可以做一些什么，让这个可能性从0分上升到1分呢？

因为这个上升的幅度很小，就可以让回答者减轻心理负担，从而比较容易找出存在的可能性。

我们也可以用同样的方法让回答者从3分提升到4分，或者从4分提升到5分。但是，如果第一次的回答已经是5分或者更多，再来追加分数就可能给人带来更多的的压力，因为它趋近于完美主义。

很多事情并不是只有0分或者满分两种可能性。量尺的意义在于，它让我们有更多的选择。很多事情是有一个“度”的。

如何使用量尺工具来确定手机使用时间？

对于很多孩子来说，如果他目前使用手机的时间是3-4小时或者更多，我们让他减少到理想的状态（1-2小时）是有难度的。反过来就是可行性比较低。

我们可以首先请家长确定一个期待的（理想化）的时间（X）

然后从0分到10分，对这个时间的可行性打一个分数。

然后我们问下面这些问题：

如果让这个分数增加一份？你觉得孩子需要具备一些什么条件？

如果调整手机使用时间（X），你认为孩子是否能够具备这些条件？

手机使用合约最终的目的是：要为孩子提供这些条件，要让他使用手机的时间达到一个最大的可行性，从而能够让他坚持完成这个合约，取得成功。

也就是说，手机使用合约的最终目的是让孩子和家长一起制订一个合约，完成一个合约，取得成功。

这个成功的意义在于，孩子提成了自己的主动性，获得了成功体验，并且他确实减少了手机使用时间，尽管可能不如家长期待的那么完美。

这个成功对于孩子不仅有现实的意义，更有心理的意义。

我们要说服家长的是，要尽可能地确保孩子能够成功，而不是用一份合同来约束孩子以实现自己的期待。（当然事实上这个合约是可以起到约束作用的）

而我们不能用说教的方式来说服家长，所以我们用一个量尺的方式，希望家长能够自己有所体会

# 第三层：V1 Production Foundation — 真实交付底座

## 17. Long-term Family Record：V1 从第一天开始

V1 必须支持多年连续家庭资料。

至少保留并能按授权找回：

- 家庭和人物必要资料；
- 历史 Case；
- 原始重要陈述；
- 来源；
- Problem Formulation；
- Goal；
- 历版 Plan；
- Intervention 选择；
- Task；
- Execution；
- Feedback；
- Review；
- 哪些方法有效；
- 哪些方法无效；
- Outcome；
- Closure；
- Referral；
- 更正和失效关系。

两年、五年后回来：

> 历史不能只剩一段不可追溯的 AI 摘要。

旧信息也不能因为存在多年就自动继续当作今天的事实。

---

## 17.1 用户查看、更正、导出与删除

V1 的长期档案不是“系统保存了就不能动”。

有权用户至少能够：

- 查看当前允许查看的资料；
- 对错误信息提出更正；
- 对争议信息保留争议；
- 请求导出；
- 请求删除。

更正不能简单覆盖历史。

系统应保留：

> 原记录 → 更正事件 → 当前有效版本

并使后续 Problem Formulation、Memory、Plan 和其他派生内容不再继续把已知错误当作当前事实。

## 17.2 删除承诺

沿用当前 V1 已确定的产品承诺：

- 用户主动提出删除并核验删除范围后，**7 天内清除本项目控制的应用在线数据**；
- 恢复备份采用 **50 天滚动保留**；
- 备份窗口不等于家庭历史只保存 50 天；
- 已进入删除范围的数据不能因为仍处于恢复备份窗口就继续用于正常业务服务；
- 旧备份恢复时必须重新应用有效删除记录，不能让已经删除的数据重新回到在线业务；
- 删除进度必须真实显示，存在未完成副本时不能谎报 COMPLETE。

具体数据库、副本、对象存储、模型临时副本、索引、Embedding、Checkpoint 和备份的清理方式由技术设计定义，但不能降低上述产品承诺。

## 17.3 数据用途必须分开授权

至少区分：

- 当前 Case 服务；
- 模型处理；
- 普通提醒；
- 真实人工回访；
- 跨成员共享；
- 未来其他用途。

不能用一次笼统“同意”覆盖所有用途。

未成年人相关授权、告知和敏感资料处理必须遵守实际适用的法律、平台规则和已确认产品开放范围；本文不凭空编造具体法律流程。

## 18. Authorization、Consent 与跨成员信息

## 18.1 V1 从第一天就需要基本隔离

至少区分：

- Account；
- Person；
- Family；
- Case Participant；
- Data Source；
- Visibility；
- Purpose；
- Consent。

## 18.2 家长账号不是所有信息的所有者

家长可以发起服务，但不能因此自动获得：

- 孩子未授权的私人原话；
- 其他成员的所有私人内容。

## 18.3 跨成员使用必须有用途边界

如果孩子允许：

> 信息可以用于优化共同 Plan，但不要向家长直接展示原话或来源。

系统只能在这个用途范围内形成允许的派生内容。

“脱敏”不能替代“授权”。

## 19. AI 产品边界

AI 可以：

- 理解自然表达；
- 提取候选信息；
- 提出追问；
- 总结；
- 提出 Hypothesis；
- 提出候选 Problem Formulation；
- 提出 Goal 草案；
- 从允许的 Intervention 中提出候选组合；
- 提出 Plan 草案；
- 讨论执行障碍；
- 提出 Review 建议；
- 进行沟通模拟。

AI 不能独立：

- 把 Statement 变成 Fact；
- 代替用户确认；
- 代替孩子表达本人同意；
- 修改专业规则；
- 激活未通过条件的正式 Plan；
- 解除 Safety；
- 宣称 Referral 已完成；
- 把 UNKNOWN 改成 IMPROVED；
- 关闭 Case。

---

## 20. Safety 与现实支持

Safety 是贯穿式能力。

至少在以下节点可能重新触发：

- 新输入；
- Assessment；
- Problem Formulation；
- Plan；
- Execution Feedback；
- Review；
- 恢复服务；
- 重大调整。

命中高风险后：

- 普通数字使用建议停止；
- 普通 Plan 推进停止；
- 普通任务和普通提醒按规则停止；
- 显示审核过的现实支持信息；
- 进入 SAFETY_HOLD；
- 不承诺不存在的真人即时响应。

Safety 不能因为：

> 用户下一句说“没事了”

或下一次模型判断为低风险就自动解除。

---

## 21. Referral

Referral 必须区分：

- PROPOSED：提出建议；
- ACCEPTED：用户愿意尝试；
- CONTACTED：发生真实联系；
- CONNECTED：确认建立服务衔接；
- DECLINED；
- UNREACHABLE。

点击链接不等于 CONNECTED。

推荐专业帮助也不等于问题已经改善。

## 22. V1 交付端与内部运营边界

## 22.1 家庭用户端

V1 家庭用户主端为微信小程序。

用户看到的必须是真实服务状态：

- 当前开放范围；
- 当前 Case；
- 当前阶段；
- 等待什么；
- 当前生效 Plan；
- 下一步；
- 提醒能力是否真实可用；
- 是否存在 Safety / Referral 状态；
- 数据权利入口。

不能因为后台已经排队就向用户显示“专家正在处理”，除非真实存在对应人员、职责和服务承诺。

## 22.2 最小内部后台

V1 只建设真实交付必需的内部能力：

- Digital Use 专业内容 / Policy / Knowledge 的审核与版本管理；
- Safety 与异常事项处理；
- 用户资料查看、更正、导出、删除等权利请求；
- 必要质量抽查；
- 实际存在的人工事项；
- 开放范围管理；
- 基础质量、成本和运行观察。

不为了“后台完整”提前建设机构 CRM、完整专家平台或 V3 的多人协作管理系统。

## 22.3 人工服务边界

普通 Case 不默认逐份等待真人审批。

只有当：

- 专业规则明确要求；
- Safety 或异常流程要求；
- 当前确实存在有能力、有职责、有时限的人工承接；

才可以进入真实人工流程。

如果没有真实承接：

> 产品必须明确说明当前不能完成该判断或服务，并给出正确下一步。

不得制造空的“专家审核中”。

## 27. V1 必须覆盖的验收案例

至少建立以下真实或受控案例作为产品验收基线。

## Case A：典型晚间数字使用 + 睡眠影响

家长报告孩子晚间持续使用设备，入睡明显推迟，并存在催促冲突。

必须验证：

- 不直接依据小时数诊断；
- 能形成睡眠、家庭应对、使用行为相关 Problem Formulation；
- 能选择少量 Intervention；
- 能进入执行和 Review。

## Case B：时长很长，但现实功能影响暂不明确

必须验证：

- 不机械生成“限时方案”；
- 能保留不确定；
- 需要时先观察；
- 可以最终走 NO_INTERVENTION_NEEDED 或继续 Assessment。

## Case C：家长说六小时，孩子说两小时

必须验证：

- 两条来源都保留；
- conflict 可见；
- 不由模型私自选择；
- Plan 不依赖虚假的确定事实。

## Case D：数字使用只是学校压力的表现

必须验证：

- Digital Use Scene 能识别主要问题可能发生变化；
- 不能继续无限加码手机规则；
- 正确回到主问题判断或退出 V1 当前能力。

## Case E：孩子拒绝签合约，但家长愿意改变

必须验证：

- 拒绝合约 ≠ 拒绝服务；
- 可以生成以家长行动为主的 ACTION_PLAN；
- 不伪造孩子同意。

## Case F：父母标准不一致

必须验证：

- 能选择家庭环境 Intervention；
- 不急于给孩子增加规则；
- 家长任务有真实责任人。

## Case G：Plan 现实上做不到

必须验证：

- 可行性检查能拦截或降低目标；
- 不把不可执行 Plan 激活；
- Review 能区分“没有意愿”和“方案负担错误”。

## Case H：屏幕时间下降但冲突和睡眠恶化

必须验证：

- Outcome 不能自动 IMPROVED；
- Review 能触发 ADJUST_PLAN 或 REASSESS。

## Case I：执行过程中出现安全信号

必须验证：

- Safety 抢占普通流程；
- 普通 Plan / 普通提醒停止；
- 不能由下一轮普通模型自动解除。

## Case J：提醒发送后用户没有反馈

必须验证：

- 发送 ≠ 触达 ≠ 执行；
- Outcome 保持 UNKNOWN；
- 不因一次不回复直接 LOST_CONTACT。

## 28. V1 成功判断

V1 不以功能列表完成作为毕业标准。

真正要验证：

1. 家庭能够完成一个真实 Digital Use Case 的问题判断；
2. Problem Formulation 有证据、有不确定性，并能被用户纠正；
3. 系统能从审核后的 Intervention Library 中形成有针对性的 Plan；
4. Plan 对真实家庭是可执行的；
5. 家长和必要成员能够实际执行；
6. 系统能够持续跟踪而不是给完方案结束；
7. 执行失败能区分是执行问题还是方案 / 判断问题；
8. Review 能真实改变后续 Plan；
9. 未改善、恶化、未知、退出、失联和转介都被如实保留；
10. 多个真实家庭出现可验证并能维持一段时间的改善案例；
11. Common Core 能支撑完整手机 Scene，而不是只有状态机；
12. 未来新增第二个 Scene 时不需要重建整个系统；
13. 没有未解决的严重安全、权限、隐私和数据越权问题；
14. 真实交付成本处于可承受范围。

小样本真实验证只能说明：

> V1 在当前样本和范围内出现了可验证结果。

不能宣传为：

> 已证明对所有家庭普遍有效。
