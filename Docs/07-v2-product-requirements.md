## 2. 版本目标与进入条件

V2 要验证：**V1 的问题解决机制可以承载更多专业场景，而不是只能处理手机问题。**

V2 延续家长为主要发起人的使用方式。先交付厌学这一新增完整场景，随后按专业成熟度逐项扩展其他儿童青少年问题。场景共用家庭资料、问题个案、计划、执行、主动跟踪、复盘、安全与结果记录。

正式开展 V2 真实家庭试点前，应取得 V1 的验收记录：

1. 手机问题能够完成判断、计划、执行、主动跟踪、复盘、调整和结果记录。
2. 多个真实家庭的完整周期记录能够支持对持续改善的判断；失败、失访和转介有单独记录。
3. 长期资料、事实来源、计划版本与提醒链路能够连续保存和恢复。
4. 阻断安全、数据可靠性或基本流程的缺陷已经解决。

若这些证据缺失，可以继续完善 V2 文档和专业内容，不能把“技术可行”当作已经具备扩张条件。

## 3. 交付范围与分期

| 阶段 | 必须交付 | 进入下一步的条件 |
|---|---|---|
| V2.0 | 手机场景回归、厌学完整闭环、共用入口与分诊、跨场景资料复用、场景内容版本管理 | 厌学专业方案通过审核，功能验收完成，进入受控真实家庭试点 |
| V2 后续增量 | 按同一准入标准逐个增加成熟场景 | 每个场景分别完成专业审核、功能验收和真实效果验证 |
| V2 阶段毕业 | 一批主要、高频儿童青少年问题可以稳定使用同一底层机制解决 | 不依赖场景数量凑达标，由第 12 节证据评审决定 |

**完成 V2.0 不等于 V2 阶段毕业。** 手机加厌学只是验证可复制性的第一步。

候选场景包括亲子沟通、学习、情绪、行为、家庭冲突、青春期、社交与成长适应。它们先进入候选清单，根据真实需求、频率、专业资料、风险和闭环可行性排序；本文不承诺全部同时上线。

本阶段不建设家庭多人独立账号协作、共同与私人空间的完整权限体系、家庭长期多问题工作台。这些属于 V3。高级风险预测、相似家庭自动推荐、实时家庭调停属于 V4；全年龄扩展属于 V5。V2 仍需记录其他已发现问题，不能因为未进入 V3 而丢失这些记录。

## 4. 用户、核心对象与用户任务

| 对象 | 本版本定义 |
|---|---|
| 发起人 | 当前使用产品的家长或照顾者；能独自启动服务，无需全家注册 |
| 家庭与人物资料 | 与问题有关的家庭背景和人物记录；人物记录不等于该人物已注册或同意某个说法 |
| 问题个案 | 持续数周或更久的问题解决过程；多次会话归入同一个案 |
| 场景 | 经审核的一组专业判断、方案、任务、跟踪、复盘和安全规则 |
| 当前主要问题 | 当前集中推进的一个问题；其他线索保留为后续观察或处理记录 |
| 计划版本 | 某次确认后的目标、行动、周期与反馈安排；后续修改保留旧版及原因 |

典型任务：

- 家长不清楚问题类型时，先描述情况，由产品帮助梳理，而非自行诊断。
- 原来处理手机问题的家长提出到校困难时，可以复用仍有效的家庭资料，再确认新增信息。
- 执行遇到阻力时，回到原个案反馈，得到针对当前阶段的支持和计划调整。
- 暂时未支持的问题得到明确说明和合适的下一步，不被包装成已经获得完整服务。

## 5. 主流程与关键分支

```text
选择成熟场景 / 自然描述
        ↓
安全筛查与初步分诊
        ↓
复用仍有效的资料 → 确认关键陈述 → 补充缺失条件
        ↓
确认当前主要问题与适用场景
        ↓
建立基线、目标、计划和执行周期
        ↓
执行 → 主动提醒 → 反馈 → 阶段复盘
                     ↑           ↓
                     └── 调整计划 / 重新判断
                                 ↓
            稳定改善 / 继续观察 / 转专业支持 / 暂停退出
```

任何阶段发现需优先处置的安全情况，可以中断普通流程。信息不足时继续了解；不满足某场景条件时重新分诊；没有成熟适用场景时说明服务边界，不能强行选择最接近的标签。

跨场景切换需要说明新增证据、切换原因、原计划如何暂停或结束、新的主要目标是什么，并由用户确认。原场景的评估、任务、反馈和结果不得被新场景覆盖。安全中断可以先暂停普通任务，再解释后续安排。

## 6. 功能需求

P0 表示相应阶段发布前必须通过；P1 表示按成熟度安排的增量，不得以“P1”隐藏一个已上线场景缺失的闭环环节。

| ID | 优先级 | 需求与业务规则 | 验收依据 |
|---|---|---|---|
| V2-F01 | P0 | 总入口同时支持选场景和自由描述；只把已经发布且适用的场景列为可启动服务 | 从两种入口均能到达正确个案；未发布场景不能开始正式干预 |
| V2-F02 | P0 | 分诊记录候选方向、已知依据、缺失条件与当前不确定性；关键信息确认后才能用于计划 | 缺条件时继续追问；互相矛盾的陈述不被自动合成事实 |
| V2-F03 | P0 | 复用家庭资料和历史方法，并显示时间、来源和适用性；变化的信息重新确认 | 再次进入时不机械重问全部资料；过期或被纠正的信息不当作当前事实 |
| V2-F04 | P0 | 厌学具备独立的入口、判断、排查、解释、计划、执行、跟踪、复盘、结果和安全边界 | 第 7 节专业包逐项审核通过，并能完成对应功能验收 |
| V2-F05 | P0 | 计划包含目标、基线、具体任务、责任人、执行障碍处理、反馈时间、复盘条件与版本 | 任务能落地执行；家长自己的改变也可成为任务；调整后可查看旧计划与原因 |
| V2-F06 | P0 | 按个案和阶段约定节奏主动提醒；用户可设置允许渠道、时间段、暂停与恢复 | 到期提醒实际走通；失败可追踪；反馈后旧提醒停止；暂停后不再发送普通催促 |
| V2-F07 | P0 | 复盘区分没执行、执行困难、方案不适合和出现新情况，并能修改目标或重新分诊 | 同一反馈会根据实际原因进入不同后续步骤；重复失败不会无限复制原方案 |
| V2-F08 | P0 | 记录阶段与最终结果；稳定改善、待观察、未改善、退出、失访和转介分开 | 未反馈不能算改善；转介建议不等于已获得专业服务；生成计划不能自动结案 |
| V2-F09 | P0 | 每个场景有草稿、审核、试点、发布、暂停和退役状态，保留专业内容版本 | 未审核版本不可对外提供完整服务；暂停时可控制新个案进入并安排存量个案 |
| V2-F10 | P0 | 风险优先、默认保护个人资料、明确 AI 服务边界；没有证据不得作临床诊断 | 风险测试会中断普通流程；跨家庭访问被拒绝；用户可理解哪些信息被保存和使用 |
| V2-F11 | P0 | 支持中断恢复、陈述纠正、查看计划与反馈历史，以及申请导出或删除资料 | 刷新与重新登录后保持真实进度；纠正保留来源；导出与删除有可查询处理结果 |
| V2-F12 | P1 | 按场景准入清单扩展下一成熟场景，并维护真实效果与失败原因分析 | 不新增独立孤岛系统；每个公开场景都通过完整准入检查 |

### 6.1 提醒与长期服务

提醒是服务的一部分，不能只在用户打开产品后显示一个红点就视为已实现主动唤醒。试点前必须选择至少一种已获得用户授权、可在产品外触达的渠道，完成真实发送与回访链路验证。渠道不可用时保留站内待办并显示触达状态，不能把站内兜底算作外部已送达。

提醒记录至少区分计划发送、已提交渠道、渠道确认送达、用户已查看、失败、取消与无法确认。供应商只返回请求受理时，不得显示“用户已收到”。通知正文默认使用中性表达，不在锁屏等外部界面披露具体家庭问题。

未反馈时按事先约定的有限次数与间隔提醒，然后进入待联系或暂停状态；没有回复不是任务完成、没有风险或问题解决的证据。系统不得承诺持续监测用户现实安全状态。

### 6.2 个案状态与结案规则

| 状态 | 含义与允许操作 |
|---|---|
| 了解中 | 收集、确认信息及分诊，不提前给出确定性根因 |
| 计划待确认 | 已形成建议，仍需用户确认目标和行动条件 |
| 执行中 | 使用当前有效计划，持续反馈和跟踪 |
| 待复盘 | 到达复盘节点；到期本身不代表已经复盘 |
| 巩固观察 | 已有改善证据，按场景规则继续观察稳定性 |
| 已暂停 | 记录原因、恢复条件及通知安排，保留完整历史 |
| 专业支持路径 | 记录建议、用户确认和实际对接进展；未获确认时保留未知 |
| 已结束 | 记录结束原因、证据、尚未解决事项及后续建议 |

“已结束”与“已解决”是不同字段。用户主动退出、失访或服务不适用可以结束个案，但不计为问题成功解决。复发时保留原结案记录，以新的处理周期关联原个案。

## 7. 厌学场景的完整专业包

本节规定专业包需要覆盖什么，不提供诊断标准或直接可执行的临床干预规则。路线图提到存在历史厌学资料，但当前仓库未包含原文；上线前必须取得原资料并逐项审查。

| 环节 | 必须形成的内容 | 边界 |
|---|---|---|
| 入口与适用性 | 家长描述的学习、到校或学校相关困难，以及服务适用范围 | “厌学”是入口表达，不直接等同问题根因 |
| 基线 | 困难何时开始、具体表现、影响、近期变化、已尝试办法、家庭条件及信息来源 | 家长转述孩子的话仍标记为家长转述，不能假装已经听到孩子本人反馈 |
| 排查 | 学习负担、学校经历、同伴关系、亲子互动、生活节律等经审核的必要维度与分支 | 不凭单项表现判定懒惰、手机成瘾或心理疾病 |
| 风险与转介 | 超出家庭教育支持范围的识别条件、专业支持路径及中断规则 | 规则与表达由合格专业负责人审核；不以普通任务替代必要的专业支持 |
| 解释与目标 | 分清事实、感受与假设；协商可执行的阶段目标 | 不默认“立刻到校”是所有个案唯一目标 |
| 计划与执行 | 与家庭条件相匹配的行动、责任、阻力处理和反馈安排 | 不引导惩罚、羞辱或强迫控制，不把改变责任全部交给孩子 |
| 跟踪与复盘 | 根据执行与变化判断继续、调整、重新分诊或升级支持 | 不把打卡次数当成问题改善 |
| 结果与观察 | 个案目标的变化、生活与家庭功能、稳定性及未解决事项 | 具体指标、观察周期和退出条件经专业审核后随场景版本发布 |

专业包应有可追溯的来源、审核人、适用年龄与条件、限制、版本、用例和修订记录。未完成审核的分支应显示尚未支持，不能让模型自行补齐后上线。

## 8. 页面与交互交付

| 页面或视图 | 用户需要完成的事 |
|---|---|
| 总入口 | 选成熟场景，或直接描述困扰，了解服务范围 |
| 个案工作区 | 看清当前主要问题、当前阶段、依据、下一步和需要补充的信息 |
| 资料确认 | 区分历史资料、当前陈述与暂时判断，确认或纠正关键内容 |
| 计划与任务 | 查看目标、责任、当前版本、具体动作、反馈和复盘安排 |
| 反馈与复盘 | 记录做了什么、阻力、变化，确认调整后的计划 |
| 个案历史与结果 | 查看计划演变和结果依据，分辨未解决、转介与稳定改善 |
| 提醒与资料设置 | 授权触达渠道、调整时间和暂停，申请资料导出或删除 |
| 最小运营视图 | 审核场景、查看版本与匿名化质量汇总，处理授权范围内的异常 |

对话入口必须始终能回到对应个案、计划和任务；不能让用户只能翻聊天记录寻找当前行动。

## 9. 质量、数据与服务要求

1. 用户陈述、确认事实、AI 假设、专业依据、计划和结果分开记录，重要记录带时间与来源。
2. 普通用户只能访问自己的授权资料；运营人员不因拥有后台账号而自动读取完整家庭对话。
3. 资料更新和计划确认失败时明确告知，不显示已经保存；重复提交不能产生多个有效计划或重复任务。
4. 模型或检索不可用时保留用户已提交信息和当前进度，说明暂时不能继续生成，不伪造正常回答。
5. 存量手机场景的流程、历史、提醒和结果必须作为 V2 回归范围。
6. 导出、删除、保留期限、未成年人信息处理及外部处理方使用范围，在真实数据进入前形成明确的产品规则和审核记录。具体期限不在缺少业务依据时编造。
7. 可用性、响应时延、通知延迟、备份与恢复目标由产品和研发在试点方案中冻结，随后按实际观测验收，不将未经测量的数字写为既有能力。

## 10. 验收场景

以下为计划执行的验收用例，不是已经通过的测试结果。

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| V2-A01 | 从手机历史进入厌学服务 | 复用并确认适用资料，保留手机历史，不重复建立全新家庭档案 |
| V2-A02 | 用户选择厌学，但当前条件不支持这一判断 | 继续排查并说明不确定性，不生成武断结论 |
| V2-A03 | 用户已自然提供必要信息 | 自然确认并进入下一缺失条件，不机械重复全套问卷 |
| V2-A04 | 计划执行失败 | 记录真实阻力，复盘并产生有依据的新版本，旧版本仍可追溯 |
| V2-A05 | 家长未按时反馈 | 按约定有限提醒，随后保留待联系或暂停；结果仍为未知 |
| V2-A06 | 普通流程出现需优先处置的风险 | 中断普通任务，进入审核过的安全路径，记录真实对接进展 |
| V2-A07 | 问题暂时改善后出现反复 | 延续观察或开启关联周期，不篡改原结果、不直接判定失败者身份 |
| V2-A08 | 场景暂停、模型失败或重复请求 | 不开放不适用的新服务，不丢数据，不重复激活计划和提醒 |
| V2-A09 | 检查原有手机流程 | 原闭环与历史可用，升级未造成已有场景退化 |
| V2-A10 | 尝试跨家庭访问、纠正与导出资料 | 越权被拒绝；本人操作有真实保存或明确失败结果 |

## 11. 效果评价与统计口径

功能验收、触达验收和真实效果验收分别记录，不能互相替代。

| 指标 | 口径 | 不允许的替代 |
|---|---|---|
| 闭环完成率 | 观察窗口内，完成已约定执行、反馈、复盘和结果记录的个案数 / 纳入同一试点队列的个案数 | 把生成计划或聊天结束计为完成 |
| 反馈回收率 | 到期后在约定窗口内取得有效反馈的节点数 / 所有已到期、未取消的反馈节点数 | 把提醒发送数当成反馈数 |
| 改善结果 | 按场景版本与个案目标记录基线、变化、证据和观察期限；报告改善、未改善和无法判断的数量 | 只展示有反馈家庭的漂亮百分比，隐去失访 |
| 稳定性 | 在预先约定的观察期检查改善是否维持，并记录复发与缺失数据 | 一次正向反馈直接计为稳定改善 |
| 分流结果 | 分开统计建议转介、用户同意、已确认对接与无法确认 | 建议转介即记为已接受专业帮助 |
| 资料复用质量 | 检查跨场景资料引用正确、过期重确认、错误可纠正，并记录失败案例 | 用检索命中率替代事实正确性 |

试点前由产品、专业负责人和运营共同确定队列纳入规则、观察时间、样本计划与效果判断标准，并保留版本；不能看完结果后再修改达标规则。当前没有这些真实观测数据，结果状态为未验证。

## 12. 发布、毕业与进入 V3 的门槛

V2.0 可发布到受控试点的条件：

- V2-F01—V2-F11 全部有验收证据；V2-A01—V2-A10 全部执行并通过；不存在未验收的 P0 项。
- 厌学专业包已逐项审查，内容来源、适用边界、安全路径和结果指标完整。
- 至少一种获授权的外部提醒渠道完成真实链路验证；失败状态和用户未回复的路径可用。
- 手机场景回归通过，迁移与备份恢复检查通过，真实数据使用规则完成审核。

V2 阶段毕业还需证明：

- 一批主要高频场景分别拥有完整闭环和真实家庭的持续结果记录。
- 同一底层机制确实被复用，新增场景无需另建独立产品。
- 失败、失访、转介、资料错误与风险事件有完整审查，不靠排除未知样本制造成功。
- 产品、专业和技术负责人共同确认多场景能力稳定，才进入 V3；不按日历时间自动升级。
