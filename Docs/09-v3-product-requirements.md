## 1. 文档依据与版本定位

本文遵循 [项目定义](01-project-definition.md) 和 [产品全景与演进路线](03-product-vision-roadmap.md) 第 5、9、11 节：**在多场景能力成熟后，让家庭成员按需要共同解决问题，同时保持各自边界，并管理家庭长期多个问题。**

V3 延续 [V2 需求文档](07-v2-product-requirements.md) 的专业场景和完整服务闭环。技术实现见 [V3 技术文档](10-v3-technical-design.md)，前序机制见 [V2 技术文档](08-v2-technical-design.md)；技术能力的上位边界见 [技术前瞻](02-technology-outlook.md)。

## 2. 目标、前置条件与范围

V3 的目标：

1. 一个人仍能启动服务；相关成员可以按需要加入同一个案。
2. 共同问题有共同目标、计划、任务和结果，个人仍拥有私人谈话与资料边界。
3. 多方陈述能够并存，冲突不会被系统武断裁决或静默覆盖。
4. 家庭能保存当前、待处理、观察、历史与复发问题，一个阶段仍只聚焦一个主要问题。

进入真实家庭试点前，必须具备 V2 阶段毕业记录：一批成熟场景已用同一底层机制稳定运行，并有真实闭环与结果证据。只上线手机和厌学菜单不构成这个前提。

本阶段交付家庭身份、按需邀请、个案参与者、共同与私人空间、明确授权、多视角、任务协作、多问题工作台、主要问题切换和存量资料安全升级。

本阶段不建设实时多人语音调停、自动风险预测、跨家庭相似案例推荐、学校与医疗机构平台、成人或全年龄产品。AI 在未获授权时利用一个成员的私人内容替另一个成员制定针对性判断，属于高复杂度能力，本版不开放。

## 3. 账号、人物与协作角色

| 概念或角色 | 能力 | 明确限制 |
|---|---|---|
| 账号 | 本人登录、私人谈话和授权操作 | 登录账号不等于家庭，也不等于家庭档案中的全部人物 |
| 人物记录 | 描述问题涉及的人及关系 | 无账号人物不被假装成已经参与或确认信息 |
| 家庭成员 | 接受邀请后拥有明确的家庭关系与成员状态 | 加入家庭不自动加入所有个案或获得历史资料 |
| 家庭协调者 | 发起邀请、协调成员关系和共同事务 | 角色本身不授予私人资料读取权，也不能代替他人同意 |
| 个案参与者 | 对获授权的个案资料、计划和任务参与反馈 | 只参与具体问题；不能浏览家庭中其他未获授权的个案 |
| 内容发布者 | 预览并授权自己有权发布的材料 | 不得转发自己无权披露的他人私人内容 |
| 专业与运营人员 | 在审核、支持或安全流程中完成获授权操作 | 后台身份不等于无限读取权，不默认存在全天人工值守 |

家长、孩子、付费者、创建者和家庭协调者是不同含义。付费或管理家庭邀请不能自动取得孩子或另一位家长的私人谈话。未成年人参与的年龄、身份与同意流程须在服务地区规则审核后启用，不能仅凭“家长邀请”视为完成全部授权。

## 4. 核心使用流程

```text
一个成员发起个案并独立推进
        ↓
发现需要其他成员参与 → 说明参与目的与所需资料
        ↓
发出邀请 → 被邀请者确认身份、关系与参与范围
        ↓
加入家庭；按另一次明确确认加入具体个案
        ↓
分别表达与确认 → 发布获授权的共同内容
        ↓
协商目标与计划 → 各自确认任务 → 分别执行与反馈
        ↓
共同复盘获授权的信息 → 调整 → 继续观察或结束
```

其他成员拒绝、尚未接受或之后退出，都不应使原发起人失去继续获得适用服务的能力。确实缺少必要参与条件时，应调整计划、降低协作要求或说明限制，不能捏造另一位成员已经同意。

## 5. 空间与授权规则

### 5.1 个人私人空间

默认包括本人对话、个人感受、未公开观察、草稿和本人尚未授权共享的历史。其他家庭成员不能凭亲属、监护、付费或协调者角色直接查看。

私人空间内提到另一位成员，不代表对方拥有这段话的读取权。把别人写入人物档案，也不等于已经取得对方账号的授权。

### 5.2 共同空间

共同内容可以包括经授权发布的问题描述、共同确认的事实、目标、计划、任务进度、复盘和结果。共同空间分为家庭范围与具体个案范围，但**空间标签本身不代表全员可见**；每次发布必须明确实际接收者。

新成员默认不能看历史内容。发布者可以预览适合该成员的历史共同材料，并重新确认授权；私人对话不因成员加入自动变成共同历史。家庭名称等用于识别邀请的最少信息，应在邀请时单独说明，不附带个案细节。

### 5.3 私人内容转为共同内容

1. 用户主动选择原文片段，或让 AI 在本人空间生成拟共享摘要。
2. 用户逐字预览待发布内容，确认有权披露，必要时修改或取消。
3. 用户选择具体接收者、用途和有效范围；系统明确将共享哪一个版本。
4. 确认后发布独立的共同内容版本，记录授权；原私人会话继续保持私人。
5. 后续修改、扩大接收者或共享新版本，都需要重新确认，不能沿用含义不明的旧授权。

私密来源在后台保留受限的追溯关系；接收者只能看获授权的内容和可公开的发布信息，不能借引用、摘要或“AI 已知背景”读到未授权原文。

### 5.4 撤回与退出

用户可以撤回自己发布内容的后续访问授权。撤回后，新访问、检索、AI 上下文、导出与后续通知应停止使用相应内容，相关派生摘要和计划草稿需要检查并失效或重新生成。

已经被他人看到、下载或自行复制的信息无法保证收回，发布前应让用户理解这一点。系统可以控制后续服务访问，不能显示“已让所有人忘记”。撤回不能擅自删除他人独立提交的资料；这些资料若引用了撤回内容，则需按依赖关系限制后续使用。

成员离开家庭或个案后立即失去对应协作权限，自己的私人空间与依法可保留资料如何处理应清楚可见。协调者不能借“移除成员”删除对方私人记录或把记录归自己所有。

## 6. 功能需求

以下 P0 均属于 V3 首次开放家庭协作前必须交付的范围，不以家庭规模或成员是否付费改变规则。

| ID | 优先级 | 需求与业务规则 | 验收依据 |
|---|---|---|---|
| V3-F01 | P0 | 区分账号、人物、家庭成员和个案参与者，保留各自状态与关系来源 | 无账号人物不会被标记为已同意；绑定人物需明确核验，不能按同名自动合并 |
| V3-F02 | P0 | 邀请可接受、拒绝、过期和撤销，说明加入的范围；不强迫全家注册 | 邀请不自动授予旧资料；拒绝后原个案仍能在适用范围继续 |
| V3-F03 | P0 | 家庭关系与个案关系分开管理，按问题邀请相关成员 | 家庭内非参与者无法查看个案；退出个案不必退出全家 |
| V3-F04 | P0 | 私人、共同及安全受限信息有明确边界，所有读取、检索和生成遵循同一权限 | 页面、接口、搜索、摘要、引用、导出和通知均不越权 |
| V3-F05 | P0 | 共享需预览、选接收者并确认具体版本；支持撤权和派生内容处理 | 未确认不能发布；加人不自动扩大权限；撤权后新请求不可再使用 |
| V3-F06 | P0 | 多方说法分开保存，区分事实、感受与解释，保留矛盾和未知 | 不能按家长身份、付费权或多数票覆盖另一人的说法 |
| V3-F07 | P0 | 共同目标和计划记录每位必要参与者的确认、分歧及未回应 | 单方确认不能显示全家同意；必要确认不足时不激活共同约束 |
| V3-F08 | P0 | 任务有明确责任人与可见范围；成员确认自己的任务并分别反馈 | 他人代录标记为转述；不能代替本人确认完成或同意 |
| V3-F09 | P0 | 多问题工作台保存主要、待处理、观察、历史和复发问题；当前仅一个主要问题 | 并发切换不能出现两个主要问题；列表、计数和排序不暴露无权个案 |
| V3-F10 | P0 | 切换主要问题、暂停、结案和复发有原因、计划处置与历史关联 | 原计划与提醒停止或按确认规则调整；切换不等于原问题已解决 |
| V3-F11 | P0 | 每位成员独立授权提醒渠道、时段与频率；内容保持最小披露 | 退出或撤权后不再收到对应通知；一个人的授权不代表全家授权 |
| V3-F12 | P0 | 安全优先且与普通家庭共享分开处理，遵循经审核的最小必要披露 | 不把全部私人资料一键发给家庭协调者；疑似施害者不因亲属身份自动成为接收者 |
| V3-F13 | P0 | 存量资料默认保留原可见范围，支持纠正、导出、删除申请和成员退出 | 无明确授权的 V2 内容不自动公开；迁移前后逐项核对 |
| V3-F14 | P0 | 提供最小的成员、授权、计划确认、质量和异常审计能力 | 可追溯谁在何时授权哪一版本给谁；普通运营不获得无关私人原文 |

## 7. 多视角与共同决策

同一事件允许并行保存：家长的观察、孩子的感受、另一位成员的解释、可确认的实际记录与暂时无法判断的部分。

例如，家长称“每天六小时”、孩子称“只有两小时”，在没有可核验记录时，应显示为两条有来源的不同陈述，且只向有权看到对应陈述的人展示。不能平均成四小时，也不能因为家长付费就确认六小时。

共同确认应明确确认了什么、由谁确认、何时确认、仍有哪些异议。单方撤回确认或提出新证据时，保留历史并重新评估有关结论；不能擦掉以前存在过分歧的记录。

共同计划的“必要参与者”由实际行动依赖决定。例如一项共同约定需要父母各自改变，则必须分别确认；某成员没有参与时，可以形成仅约束已确认成员的计划，不能替未参与者承诺。

## 8. 多问题管理与单一主要问题

| 分类 | 产品含义 | 跟踪方式 |
|---|---|---|
| 当前主要问题 | 本阶段唯一集中推进的家庭问题 | 完整计划、执行、反馈与复盘 |
| 已发现待处理 | 有线索，已记录但尚未开始正式推进 | 保存来源、排序理由与再次查看条件 |
| 暂停 | 曾经启动，因明确原因暂停 | 保存恢复条件；取消不再适用的普通提醒 |
| 观察或巩固 | 需要观察变化或稳定性 | 按明确约定安排观察，不偷偷开启第二套完整干预 |
| 历史结束 | 已记录结束原因与结果 | 区分稳定改善、未解决、退出、失访和转介 |
| 复发或再次处理 | 与历史问题有关的新处理周期 | 链接原问题与结果，不覆盖历史 |

“分类”是工作台视图；个案状态、效果分类和是否为主要问题是不同维度，不能用一个标签承载全部含义。

切换前说明：为何现在更重要、当前个案如何处置、哪些任务取消、保留哪些观察、谁需要确认以及下一次复盘是什么。切换由有权协调且能访问受影响个案的参与者确认；家庭协调者不能盲目操作一个自己无权读取的个案。

私人求助草稿可以存在，但不自动成为全家新的主要问题。主要个案的存在与内容也应受权限控制；其他成员不能通过全家问题总数、错误消息或空白卡片推断无权资料。

风险处置是优先中断规则，可以先暂停普通主要问题；它不意味着同时开启多个普通干预。风险解除后需重新确认恢复条件，不能自动继续旧任务。

## 9. 页面与协作体验

| 页面或视图 | 用户需要看清的内容 |
|---|---|
| 我的空间 | 私人对话、草稿、本人记录，以及哪些内容已经对外授权 |
| 家庭与成员 | 已接受成员、邀请状态、关系和协调职责，避免展示无权资料 |
| 邀请与参与确认 | 参与目的、加入家庭与加入个案的区别、当前会获得哪些资料 |
| 个案共同工作区 | 有权读取的问题、共享事实、分歧、目标、计划及下一步 |
| 共享预览 | 准确文本、接收者、版本和撤回后的实际限制 |
| 共同计划确认 | 自己的任务、必要确认、未回应或不同意的真实状态 |
| 我的任务与反馈 | 只呈现本人或获授权的任务，可记录真实阻力与变化 |
| 家庭问题工作台 | 有权查看的主要、待处理、观察和历史问题；不显示无权项目计数 |
| 授权与退出 | 查看授予谁哪些内容，撤回、离开个案或家庭，申请导出与删除 |
| 最小支持后台 | 在授权范围内查询邀请、权限与作业异常，保留访问审计 |

角色可以影响表达方式与任务展示，但不必提前建设彼此独立的爸爸端、妈妈端和孩子端应用。是否分客户端由真实体验需要决定。

## 10. 安全、隐私与资料升级

1. 安全规则可以优先打断普通服务，但不等于自动公开全部私人信息。接收人、目的、字段、依据和责任人应在安全规则中明确。
2. 服务地区、未成年人同意、身份与监护关系、应急资源及人工支持范围应在启用相关功能前审核。本文不代替法律意见，也不虚构应急联系人或全天响应承诺。
3. 从 V2 升级时，原记录默认保持原所有者可见。邀请家人后，用户逐项选择可共享材料；不能把旧对话批量归为全家共同资料。
4. 人物绑定、家庭合并或重复记录合并需要正面证据与明确确认。同名、同手机号线索或同一地址不足以自动合并敏感档案。
5. 退出、撤权、导出与删除应明确影响本人材料、共同材料和他人独立记录的范围；保留例外与期限经过审核并可说明。
6. 没有权限的资料不能通过模型输入、派生总结、搜索建议、通知、附件、统计或导出绕过限制。

## 11. 验收场景

本表是计划执行的验收场景，不表示测试已经运行或通过。

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| V3-A01 | 妈妈单独发起，爸爸拒绝邀请 | 不强迫爸爸注册；记录未参与，调整为可由妈妈执行的计划 |
| V3-A02 | 孩子加入家庭但未加入个案 | 看不到该个案内容和历史，也不能收到相关敏感通知 |
| V3-A03 | 协调者或付费家长尝试读取另一人的私人谈话 | 页面、接口、检索和 AI 回复均不能泄露 |
| V3-A04 | 用户预览摘要后取消共享 | 不产生共同可见内容或授权；后台不发送共享通知 |
| V3-A05 | 发布后修改摘要或新增接收者 | 生成新版本并重新确认；旧授权不自动扩展 |
| V3-A06 | 两方陈述矛盾且证据不足 | 保留各自来源和未知；不平均、不投票、不按身份裁决 |
| V3-A07 | 一人同意计划，必要参与者未回应或反对 | 不显示全体同意；不得替对方激活承诺 |
| V3-A08 | 他人为孩子代录完成情况 | 明确为转述，不能记作孩子本人已确认 |
| V3-A09 | 两位成员同时切换主要问题 | 只成功一次，另一方收到需刷新并重新确认的冲突提示 |
| V3-A10 | 成员退出、内容撤权时仍有缓存与未发送通知 | 后续读取、生成、导出和通知重检权限并停止越权使用 |
| V3-A11 | V2 历史升级并邀请新成员 | 旧私人历史保持隔离，只共享明确确认的版本与接收者 |
| V3-A12 | 私人空间出现需要优先处置的风险 | 进入审核路径，最少必要披露，不自动通知所有家人 |
| V3-A13 | 结案后复发或发现另一问题 | 保留原结果，建立关联周期；一次只集中推进一个主要问题 |
| V3-A14 | 成员尝试通过计数、搜索、引用、错误消息和导出发现无权资料 | 所有出口遵循同一权限，不能旁路推断或读取 |
| V3-A15 | 迁移遇到所有者、来源或授权不明的记录 | 保留并隔离为待核对，不删除、不公开、不补造确认 |

## 12. 协作价值与结果评价

继续使用 V2 的真实问题改善与稳定性指标，并增加以下评价：

| 评价方向 | 观察内容 | 统计边界 |
|---|---|---|
| 协作必要性 | 被邀请成员为何需要参与，加入后是否帮助推进问题 | 邀请多、注册多不等于协作有效 |
| 计划可执行性 | 必要成员确认情况、任务承担、执行障碍及复盘变化 | 未回应与不同意分别记录，不算已同意 |
| 多视角质量 | 来源保留、错误纠正、分歧处理与后续验证 | 矛盾减少可能只是没有发声，不能单独视为改善 |
| 边界可信度 | 用户是否理解共享范围，授权、撤权与越权测试是否按约定生效 | 任何权限泄露均作为阻断缺陷，不被平均满意度抵消 |
| 多问题连续性 | 切换是否有理由、未处理问题是否保留、历史是否连续 | 不按同时活跃问题数量评价产品价值 |
| 家庭实际结果 | 依预先约定的目标与观察窗口，报告改善、未改善、失访、退出和转介 | 不因为更多成员填写了表单就认定问题已解决 |

试点前冻结纳入规则、样本计划、观察周期和评审方法，分别报告单人个案与多人个案。没有可比较证据时，不宣称多人协作比单人一定更有效。

## 13. 发布、毕业与后续条件

首次开放家庭协作前：

- V3-F01—V3-F14 全部有验收证据，V3-A01—V3-A15 全部执行并通过，未审核与未验收 P0 项为零。
- 共享、撤权、退出、跨家庭及同家庭越权测试通过；所有派生资料和通知出口纳入验证。
- 存量迁移逐项核对，原总数与各状态之和一致，待核对记录有保全和处理安排。
- 未成年人参与、安全处置与人工支持边界经过审核，不能公开未获支持的服务能力。
- V2 的专业闭环、主动跟踪与原有个案回归通过，备份恢复和权限撤销重放完成演练。

V3 阶段毕业还需真实家庭证明：不同成员可以在保持边界的前提下共同执行并复盘；家庭长期多个问题可以有序保存和切换；长期资料与结果连续可用。进入 V4 还需要足够且质量可靠的连续数据及新的专业验证，不能因为协作功能上线就直接启用预测或实时介入。

## 14. 实施前需完成的明确决策

| 决策或材料 | 责任角色 | 未完成时的限制 |
|---|---|---|
| V2 毕业记录与实际代码、数据、权限基线 | 产品、专业、研发 | 不假定具备 V3 试点前提 |
| 成员身份、未成年人参与及关系核验方案 | 产品、隐私与合规负责人 | 不开放未经审核的成员类型或流程 |
| 各场景必要参与者与共同计划确认规则 | 专业负责人 | 不用统一“全员必须同意”或“创建者说了算”替代专业条件 |
| 安全例外、接收者选择、人工支持与处置时限 | 专业、运营及规则审核人员 | 不允许模型自行扩大披露，不承诺未提供的值守 |
| 共享撤回、退出、保留、导出与删除规则 | 产品、隐私与研发 | 不自动公开、转移或销毁存量敏感内容 |

这些决定应在实施相应能力前形成可追溯版本，并保持与本需求文档和技术文档一致。
